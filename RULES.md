## Participation and building

1. **Solo hackathon.** You participate as an individual, with no team.
2. **The theme is open.** Bring an idea and build something you wish existed.
3. **Start from scratch at the event.** Libraries, APIs and public datasets are welcome. Pre-built projects are not allowed.
4. **Build with Devin.** The event is about AI-assisted software development with Devin. Keep a short, accurate record of how AI tools were used in [AI_USAGE.md](AI_USAGE.md).
5. **Submit your code repository, a short project description and a working demo**, following the organizers' submission instructions. [SUBMISSION.md](SUBMISSION.md) collects these items.

## Persistent Project Context and Documentation Maintenance

These are project rules for every contributor, human or AI. They add no event eligibility requirements.

1. **[PROJECT_CONTEXT.md](PROJECT_CONTEXT.md) is the canonical shared project context.** Read it, together with [AGENTS.md](AGENTS.md), before substantial work, and verify it against the actual repository and `git status`.
2. **Keeping documentation current is part of finishing a task.** Any meaningful change to features, architecture, dependencies, APIs, schema, integrations, security, requirements, the roadmap or known limitations must update the relevant sections of `PROJECT_CONTEXT.md` in the same task, along with `CHANGELOG.md` and, where applicable, `README.md` and `AI_USAGE.md`.
3. **Accuracy over completeness.** Record only verified status. Never claim untested work is complete, never invent details, never treat ideas as approved requirements, and never expose secrets. Label uncertainty explicitly.
4. **Make targeted updates and preserve existing knowledge.** Don't rewrite the context file for small changes. Keep valid decisions and outstanding requirements, and record superseded decisions briefly.
5. **Keep it agent-agnostic.** The context must stay usable by any AI coding environment and must not rely on any tool's private memory or session state.
6. **Reconcile at the end of each task.** Before calling substantial work done, check that the feature inventory, bugs, roadmap, current state and handoff instructions are accurate, and add a row to the Context Maintenance Log.

The full, detailed version of these rules is in [AGENTS.md](AGENTS.md#persistent-project-context-and-documentation-maintenance).
